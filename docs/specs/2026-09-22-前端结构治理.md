# 前端结构治理

日期：2026-09-22
上游：`CONTEXT.md`（术语）、`docs/adr/0001`、`docs/adr/0002`、`docs/adr/0003`

---

## 1. 问题陈述

`frontend/` 共 5870 行 / 15 个文件，其中三个占 58%，每个都承载多个互不相关的职责：

| 文件 | 行数 | 混在一起的东西 |
|---|---|---|
| `widgets.py` | 1444 | 14 个部件类：转录内容块、工具调用视图、审批面板、状态栏、侧栏、输入区、内联面板，加上 token 口径与各种格式化函数 |
| `app.py` | 1047 | `LrmneCodeApp` 一个类 71 个方法 + 256 行 CSS：组装、键位、协议收发、会话生命周期、命令执行、@ 提及、浮窗编排 |
| `overlay.py` | 914 | 4 种浮窗 + `Overlay` 基类 + 约 130 行 `OVERLAY_CSS` |

**后果**：读一个功能要在大文件里跨几百行找目标；新增部件没有天然归属；同一件事的实现散落多处
（`frontend/tools.py` 有纯逻辑、`results.py` 有视图辅助、`widgets.py` 里又各写一遍格式化）。

本次工作是**治理**（定义见 `CONTEXT.md`）：只改代码结构，不改用户可观察的行为与外观。

## 2. 方案概述

三个巨大文件各自变成**同名包**（`widgets/`、`overlay/`、`app/`），包内按职责分模块，单模块 ≤400 行；
包名保持不变，`__init__.py` 原样转发既有外部导入路径。

顺序先建**渲染快照基线**（重构前的真值），再自底向上切片搬运：`widgets` → `overlay` → `app` → 收口守卫测试。

依赖方向（已核实）：`widgets` 是叶子（无任何外部消费者，仅 `app`/`conversation`/`events`/`results` 四处内部导入）；
`overlay` 不导入 `widgets`，自包含；`app` 在最上层，依赖两者。`backend/`、`handlers/`、`proxy_layer/`
没有任何一处导入 `frontend`，本次改动不波及后端。

## 4. 用户故事

- **US-1 外部路径不变**：`frontend.overlay.SessionSwitcherOverlay`、`frontend.app.LrmneCodeApp`、
  `frontend.conversation`、`frontend.commands`、`frontend.mentions`、`frontend.theme`、`frontend.tools`、
  `frontend.client` 的导入路径与符号全部照旧可用。
- **US-2 行数达标**：`frontend/widgets/`、`frontend/overlay/`、`frontend/app/` 下每个 `.py` ≤400 行。由守卫测试断言。
- **US-3 渲染零变化**：每个切片完成后，快照基线与重构前逐字一致。
- **US-4 行为零变化**：246 个测试全绿。**唯一允许的测试改动**是 `conftest.py` 的 patch 目标（见 §7）。
- **US-5 切片独立可验**：每个切片单独提交，测试 + 快照全绿才提交；变红可立即定位到该切片并单独回滚。
- **US-6 `@on` 入口留在 App 类**：6 个 `@on` 装饰的处理器不允许搬进 mixin（框架约束，见 ADR-0003）。
- **US-7 App 类不拆类**：`LrmneCodeApp` 始终是单一类，通过 mixin 组合扩展，不改继承以外的类结构。

## 5. 已定决策

1. **治理对象**＝代码结构。视觉/交互改动不在本次范围。
2. **验收方式**＝先建渲染快照基线，再动结构；每切片跑全量测试 + 快照比对。
3. **目标结构**＝三个大文件各自变包，包内按职责分；外部路径靠 `__init__` 转发（ADR-0001）。
4. **治理深度**＝搬运 + 消除确实重复；**不重建巨型类的内部结构**（`ToolCallView`、`ModelConfigOverlay`
   等方法体不动）。
5. **收口标准**＝单模块 ≤400 行。
6. **顺手边界**＝允许删死代码/未用导入、补类型标注、按 `CONTEXT.md` 术语表重排命名；
   **发现功能缺陷只记不修**，另开一轮。
7. **执行节奏**＝自底向上切片，一片一提交。

**查证后对上述决策的三处修正/补充：**

- **修正 ⑨-1**：包名**不**改成 `overlays/`，保持 `overlay/`。改成复数会让
  `from frontend.overlay import SessionSwitcherOverlay` 失效，违反 US-1。同理 `app/` 保持单数。
- **补充 ⑨-2**：`app.py` 的类拆分必须采用"**mixins 承载实现 + 6 个 `@on` 入口留在 App 类**"的形式。
  Textual 8.2.8 不为普通 mixin 收集 `@on` 处理器（实测 + 源码确认，见 ADR-0003）。
- **补充 ⑨-3**：`conftest.py` 的 `monkeypatch.setattr(app_module, "BackendClient", FakeClient)` 目标
  必须改到**调用处所在的模块** `frontend.app.main`——唯一允许的测试改动，理由见 §7。

## 6. 测试决策

**接缝（复用已有，不新建）**：`test/test_frontend/conftest.py` 的 `make_app` fixture 已经把
`BackendClient` 换成 `FakeClient`（不拉子进程），测试用 `app.run_test()` + `pilot.pause()` +
`emit()` / `_handle_receipt()` 驱动。快照基线直接复用这个接缝。

**快照基线**：
- 机制：`App.export_screenshot()`（Textual 8.2.8 提供，返回含样式的 SVG）。不引入 `pytest-textual-snapshot`
  等新依赖。选它而不是纯文本渲染，是因为本次要防的坑——CSS 作用域被 `SCOPED_CSS` 改写、`mount` 晚一拍、
  私有属性撞名、字形退化成 emoji——**全都只体现在样式与行内容上**，纯文本看不出来。
- 覆盖（6 屏）：① 应用外壳初始态 ② 转录区（助手块流式中/完成、思考块、工具块折叠与展开、diff 折叠）
  ③ 审批面板 ④ `Picker` ⑤ `ModelConfigOverlay` ⑥ `SessionSwitcherOverlay`
- 固定终端尺寸（`run_test(size=...)`），基线存 `test/test_frontend/snapshots/*.svg`，用环境变量
  （如 `LRMNE_SNAPSHOT_UPDATE=1`）重新生成。
- 守卫：`frontend/widgets|overlay|app` 下每个 `.py` ≤400 行。

**确定性**：时间驱动的文本与周期任务会让同一屏在两帧之间翻转，切片 0 已把这件事解决掉，
做法与踩到的三个坑见 §7.1。基线可复现已验证：同一份代码连跑三遍逐字一致。

**"完成"长什么样**：`pytest test` 246+ 全绿；快照逐字一致；守卫测试通过；三个包下无 >400 行的模块。

## 7. 为什么只允许改这一行测试代码

`conftest.py` 目前靠 `monkeypatch.setattr(app_module, "BackendClient", FakeClient)` 阻止测试拉起后端子进程。
Python 的模块全局查找发生在**代码所在模块**的命名空间里：`app.py:352` 的 `BackendClient(...)`
读的是 `frontend.app.__dict__`。一旦这个方法搬进 `frontend.app.mixins.sessions`，
`frontend.app.__dict__` 上的 patch 就再也影响不到它——而且**不会报错**，只会真的去拉子进程。

解法是把 patch 目标挪到**调用处所在的模块**：`monkeypatch.setattr(app_main, "BackendClient", FakeClient)`
（`from frontend.app import main as app_main`）。这不是"放宽安全网"，而是把 patch 打在真正会被查询的那张
命名表上——打在包名或定义处都不会生效，且**失败形态是测试真的去拉后端子进程**。
除此之外，`test/test_frontend/` 下不得修改任何既有断言。

同一条规律也解释了快照夹具为什么要逐个模块打补丁：`from X import name` 绑的是各模块自己的全局，
拆包后只打顶层包名会静默失效（`_fmt_elapsed` 就是这么躲过一次 patch 的）。

## 7.1 渲染快照实际怎么做到确定

实测三件事，都不在代码里读得出来：

1. `App.export_screenshot()` 的 SVG 带**随机样式类名**（`terminal-<id>`），比对前必须折掉；
   会话号 `c-<8hex>`（含裸显示的形式）同理。
2. 应用挂着周期任务（0.2s 贴底兜底 tick、spinner、思考块耗时），实测会让同一屏在两帧之间**反复翻转**；
   8.2.8 没有 `App.freeze()`，靠遍历各部件的 `_timers` 停表。
3. 真正毁掉确定性的不是像素而是**文字长度**：耗时从 `0ms` 变成 `1.0s` 多出一格，内容高度被推过滚动条
   阈值，整块宽度跟着抖一格。解法是钉住 `_fmt_elapsed` 返回定宽字符串——不能冻 `time.monotonic`，
   那会让 Textual 的定时器空转挂死。

钉住长度之后，坐标、宽度、样式类索引、可见字符**全部保留**参与比对，这张网没有被放宽。

## 8. 明确不做

- 不改视觉与交互：不调间距、颜色、字形、文案、键位。
- 不重建巨型类的内部结构：`ToolCallView`(305 行)、`ModelConfigOverlay`(245 行)、`SidePanel`(223 行)
  的方法体与内部子部件组织保持不变。
- 不修功能缺陷：过程中发现的 bug 记入清单，不夹带修复。
- 不纳入 `conversation.py`(359)、`results.py`(338)、`tools.py`(330)：本就在 400 行线内。
- 不碰 `proxy_layer/`、`backend/`、`handlers/`（既有边界，见 §2 依赖方向）。
- 不引入新依赖。

## 9. 补充说明

- 事件渲染器（`events.py`）与结果渲染器（`results.py`）是**导入即注册**的，`app` 包必须保证
  `from .. import events` 这类副作用导入仍然执行一次，否则整张分发表会空掉。
- `overlay.py` 的 `Overlay` 基类上写着 `SCOPED_CSS = False`，这是为了让基类 CSS 里的
  `Overlay { align: center middle }` 不被作用域改写——搬家时这个属性和它的注释必须跟着走。
- 切片 3 的 `app/` 包会同时动 CSS 常量与类结构，是风险最高的一片；前两片全绿后再动它。
