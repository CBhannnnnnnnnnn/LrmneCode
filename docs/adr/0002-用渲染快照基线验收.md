# 用渲染快照基线验收"功能未变"

本次前端治理的硬约束是"不改变现有功能"，但现有自动化安全网只有 `test/test_frontend` 的 8 个文件，
其中唯一的渲染级断言只有 `test_app_shell.py:690` 一处 `render_line(0)`；原先用来做渲染验证的
`scripts/preview_*.py` 5 个无头预览脚本已在 `a7fda97` 删除，`scripts/` 目录整体不存在。

决定：重构开始前，先把关键屏（应用外壳 / 转录区 / 工具块 / 四个浮窗）在固定终端尺寸下的渲染结果
（含样式）固化成快照基线，**单独提交**；之后每个重构切片都跑全量前端测试 + 快照比对，逐字一致才算通过。

**Why:** 本项目踩过的坑——CSS 被 SCOPED_CSS 作用域改写、`mount` 晚一拍导致结果被丢弃、私有属性撞名把
挂载钩子顶掉、字形退化成 emoji——**全都不会让行为断言变红**，只会让界面静默变样。只靠 `test_frontend`
无法证明"外观也没变"。基线在重构前生成，天然就是真值，成本是一次性的。
