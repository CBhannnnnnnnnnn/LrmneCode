# 前端三个巨大文件拆成包，对外路径由 `__init__` 转发

`frontend/widgets.py`（1444 行）、`app.py`（1047 行）、`overlay.py`（914 行）合计占前端 5870 行的 58%，
每个文件都承载多个互不相关的职责，需要在不改变用户可观察行为的前提下治理。

决定：三者各自变成包（`widgets/`、`app/`、`overlays/`），包内按职责分模块；
`frontend.overlay.SessionSwitcherOverlay`、`frontend.app`、`frontend.conversation`、`frontend.commands`、
`frontend.mentions`、`frontend.theme`、`frontend.tools` 这些被测试导入的路径，在包的 `__init__.py` 里原样转发，
测试文件零改动。

**Why:** 前端是自包含的——`backend/`、`handlers/`、`proxy_layer/` 没有任何一处导入 `frontend`，
布局调整不波及后端；且 `widgets.py` 没有任何外部消费者（只有 `app` / `conversation` / `events` / `results`
四处内部导入），成包的代价只有一层目录。不采用同级平铺（`frontend/` 会从 15 个文件涨到约 28 个，目录失去边界），
也不保留老文件做兼容转发（会让仓库长期存在两套路径，"治理"退化成"加一层"）。
